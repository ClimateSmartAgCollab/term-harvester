# AgriFoodCA Picklist Pipeline

This directory contains the tooling that transforms `schema.yaml` (the LinkML
schema produced by `term_harvester.py`) into `entry_code_picklists.json` (the
JSON picklist file consumed by DataHarmonizer).

## Files

| File | Role |
|------|------|
| `agrifoodca_config.yaml` | `term_harvester.py` config: source registry, locale settings, and per-source filters — controls generation of `schema.yaml` |
| `schema.yaml` | Input — LinkML schema built by `term_harvester.py -b` |
| `entry_code_picklists.json` | Output — JSON picklist file for DataHarmonizer |
| `agrifoodca_mapping.yaml` | Mapping/diff config between schema and JSON |
| `agrifoodca_sssom.tsv` | French translations not covered by the schema |
| `schema_to_picklists.py` | Script that reads the above and produces the JSON |

---

## `agrifoodca_mapping.yaml`

This file is the bridge between the schema's enum representation and the JSON
picklist format.  It is consumed by `--build` (which outputs a new
`entry_code_picklists.json` file) and contains **all enumerations** that appear
in `entry_code_picklists.json`.

The file has two top-level sections:

### `schema_to_json`

Controls which schema enums are included in `entry_code_picklists.json` by
mapping schema enum keys to JSON picklist keys:

```yaml
schema_to_json:
  AgriFoodCA_AgreementScale: agreement_scale
  STATSCAN_1313722: education_level_stats_can
  ...
```

Add or remove entries here and re-run `--calibrate` to update the `enums`
section, then `--build` to regenerate the JSON.  Enums absent from this map
will not appear in the output even if they exist in `schema.yaml`.

Use `--add SchemaEnumKey:json_key` to add a new entry automatically (see
[Adding a new enum](#adding-a-new-enum-from-schemayaml) below).

### `enums`

Per-picklist configuration regenerated by `--calibrate` and consumed by
`--build`.  Each key is the JSON picklist key (e.g. `agreement_scale`).

| Field | Purpose |
|-------|---------|
| `schema_key` | The enum name in `schema.yaml` when it differs from the JSON key (e.g. `AgriFoodCA_AgreementScale`). Required for all schema-backed enums. |
| `static: true` | Marks enums with no backing schema enum; all content is defined directly in this file. |
| `id` | Integer sort key used to order picklists in the output JSON. |
| `name.en` | English name override (when it differs from the schema enum's `title`). |
| `description.en` | English description override. |
| `keywords` | Keyword map `{keyword: {en: ...}}` for search/discovery metadata. |
| `category` | Picklist category string (e.g. `"general"`, `"soil"`). |
| `source` | Attribution URL for the picklist. |
| `languages` | List of language codes present in the output rows (e.g. `["en", "fr"]`). |
| `extra_mappings` | Additional column names beyond `Code`/`en`/`fr` (e.g. `short_code`, `SGC_code`, `Month_number`). |
| `permissible_values` | Per-code overrides: `schema_key` (when the JSON Code differs from the schema PV key), `en` (English label override), and any extra column values. |

**When to edit this file directly:**
- To correct an English label that differs from both the schema and the
  reference JSON (add an `en:` override under `permissible_values`).
- To add or update `keywords`, `category`, or `source` metadata.
- To add extra column values (`short_code`, `SGC_code`, etc.).
- `was_en` values are generated by `--calibrate` and are informational only —
  do not edit them manually; `--build` ignores them.
- After editing, run `--build` to regenerate `entry_code_picklists.json`.

## `agrifoodca_sssom.tsv`

This file stores French translations in
[SSSOM](https://mapping-commons.github.io/sssom/) (Simple Standard for Sharing
Ontological Mappings) TSV format.  It covers translations that are not already
present in `schema.yaml`'s locale extensions.

Subject ID patterns:

| Pattern | Covers |
|---------|--------|
| `agrifoodca:{json_key}:name` | French name for the picklist |
| `agrifoodca:{json_key}:description` | French description for the picklist |
| `agrifoodca:{json_key}:keywords:{kw}` | French translation of a keyword |
| `agrifoodca:{json_key}:choice:{Code}` | French label for a specific row |

The `object_label` column carries the translation with a BCP-47 language tag,
e.g. `"Femme"@fr`.

**This file is fully regenerated by `--calibrate`** — do not edit it manually
unless you need to patch a single translation without re-running calibration.

Translation priority during `--build` (highest wins):
1. `agrifoodca_sssom.tsv` entry for the code
2. Schema locale extension (`schema.yaml` `extensions.locales.fr`)
3. `fr:` override in `agrifoodca_mapping.yaml`

## Workflow

### Normal rebuild of entry_code_picklists.json (schema changed, mapping unchanged)

```bash
python schema_to_picklists.py --build
```

Reads `schema.yaml` + `agrifoodca_mapping.yaml` + `agrifoodca_sssom.tsv` and
writes `entry_code_picklists.json`.  Run this after any `term_harvester.py -b`
that affects picklist enums.

### Calibrate (JSON picklist is the reference; update mapping to match)

```bash
python schema_to_picklists.py --calibrate
```

Reads `schema.yaml` + the current `entry_code_picklists.json` (treated as
ground truth) and regenerates both `agrifoodca_mapping.yaml` and
`agrifoodca_sssom.tsv` to reflect it.  Run this when:

- `entry_code_picklists.json` has been manually edited and the mapping/SSSOM
  need to catch up.
- The JSON picklist keys have been renamed (update `schema_to_json` in
  `agrifoodca_mapping.yaml` first).
- A new enum has been added to `entry_code_picklists.json`.

After `--calibrate`, run `--build` to verify the round-trip is exact:

```bash
python schema_to_picklists.py --calibrate
python schema_to_picklists.py --build
```

The rebuilt JSON should be identical to the reference (modulo a trailing
newline).

### Adding a new enum from schema.yaml

```bash
python schema_to_picklists.py --add SchemaEnumKey:json_picklist_key
```

Registers the enum by:
1. Adding `SchemaEnumKey: json_picklist_key` to the `schema_to_json` section of
   `agrifoodca_mapping.yaml`.
2. Creating the enum entry in the `enums` section with all permissible values
   pre-populated (code + English label) from `schema.yaml`.
3. Rebuilding `entry_code_picklists.json`.

Add `keywords`, `category`, and `source` to the new `enums` entry manually
afterwards as needed, then run `--build` again.

Re-running `--calibrate` after `--add` is safe — the entry persists in
`schema_to_json` and is regenerated correctly from the now-updated
`entry_code_picklists.json`.
